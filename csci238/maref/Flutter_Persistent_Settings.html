Flutter: Shared Preferences and Persistent Settings

Applications often need to remember user preferences between sessions. A settings screen, for example, is of little value if the user must select a theme and enter a name every time the application starts. This chapter introduces persistent key-value storage in Flutter through a working settings application. It also explores how to customize the installed application name and launcher icon.

Familiarity with Dart, StatefulWidget, setState(), TextField, Future, and basic Flutter layouts is assumed.

Application state and persistent storage

When a user enables dark mode, the application is expected to remember that choice the next time it opens.

A Flutter StatefulWidget can remember a value while the widget is alive. But a normal variable is not automatically saved when the operating system terminates the application. Calling setState() redraws the interface; it does not save a value to disk.

You will give your application a small amount of memory:

  • A display name, stored as a String.
  • A dark mode setting, stored as a bool.
  • A text size setting, stored as a double.

You will change each setting, fully close the application, reopen it, and check whether your selections are restored.

Other common application preferences include a preferred language, whether introductory hints are shown, and a default sort order.

Shared preferences and key-value pairs

The shared_preferences plugin provides simple, platform-backed key-value storage. We give each value a key (a string identifying it) and store a supported value under that key.

Key Type Example value
display_name String Alex
dark_mode bool true
font_size double 22.0

The package supports int, double, bool, String, and List<String>. A read of an absent key produces null, so we supply defaults using the ?? operator:

final String name = await prefs.getString('display_name') ?? '';
final bool dark = await prefs.getBool('dark_mode') ?? false;
final double size = await prefs.getDouble('font_size') ?? 18.0;

Why SharedPreferencesAsync? Current package guidance recommends SharedPreferencesAsync or SharedPreferencesWithCache for new work. SharedPreferencesAsync performs asynchronous reads against platform storage instead of relying on a local cache. It works with Future and await and avoids cache-staleness surprises. The older SharedPreferences.getInstance() API still appears in many online examples, but it is designated legacy in the current documentation.

Limitations: This is suitable for small, noncritical preferences, not a relational database, large datasets, passwords, access tokens, or financial/medical records. It is not an encrypted secrets store. The plugin documentation also warns that disk persistence is asynchronous and not guaranteed to complete before abrupt termination, even after the write call returns. Do not treat it as transactional durable storage.

Connection to SQLite: SQLite stores structured records that can be queried. Shared preferences store a few named values. Use the simplest tool that fits the data.

Installation

Open a terminal in Visual Studio Code:

flutter doctor
flutter create persistent_settings_demo
cd persistent_settings_demo
code .

Install the dependency:

flutter pub add shared_preferences

This updates pubspec.yaml and resolves a compatible package version. The current package listing is shared_preferences on pub.dev; use the version selected by flutter pub add rather than hard-coding a version from an older tutorial.

Open lib/main.dart. Replace its contents with the complete code in the following section. Then run:

flutter run

An Android emulator, iOS simulator, or physical phone is sufficient. No platform permission dialog is needed for ordinary preference storage.

Build the settings application

The application has three editable settings, a name-saving button, a restore-defaults button, and a live preview. The theme and text-size selections save as they change. The name saves when you press Save Name.

import 'package:flutter/material.dart';
import 'package:shared_preferences/shared_preferences.dart';

void main() {
  runApp(const SettingsDemoApp());
}

class SettingsDemoApp extends StatefulWidget {
  const SettingsDemoApp({super.key});

  @override
  State<SettingsDemoApp> createState() => _SettingsDemoAppState();
}

class _SettingsDemoAppState extends State<SettingsDemoApp> {
  // Keys are constant names for values stored on the device.
  static const String nameKey = 'display_name';
  static const String darkModeKey = 'dark_mode';
  static const String fontSizeKey = 'font_size';

  // Current recommended asynchronous preferences API.
  final SharedPreferencesAsync _prefs = SharedPreferencesAsync();

  // Controller for the editable display name.
  final TextEditingController _nameController = TextEditingController();

  // Allows this root widget to show a SnackBar from its methods.
  final GlobalKey<ScaffoldMessengerState> _messengerKey =
      GlobalKey<ScaffoldMessengerState>();

  bool _loading = true;
  bool _darkMode = false;
  double _fontSize = 18.0;
  String _savedName = '';

  @override
  void initState() {
    super.initState();
    _loadSettings();
  }

  // Read the settings when the application starts.
  Future<void> _loadSettings() async {
    try {
      final String name = await _prefs.getString(nameKey) ?? '';
      final bool dark = await _prefs.getBool(darkModeKey) ?? false;
      final double size = await _prefs.getDouble(fontSizeKey) ?? 18.0;

      if (!mounted) return;
      _nameController.text = name;
      setState(() {
        _savedName = name;
        _darkMode = dark;
        _fontSize = size.clamp(14.0, 30.0).toDouble();
        _loading = false;
      });
    } catch (error) {
      if (!mounted) return;
      setState(() => _loading = false);
      _showMessage('Could not load settings: $error');
    }
  }

  void _showMessage(String message) {
    _messengerKey.currentState
      ?..hideCurrentSnackBar()
      ..showSnackBar(SnackBar(content: Text(message)));
  }

  // Save the display name when the Save Name button is pressed.
  Future<void> _saveName() async {
    final String name = _nameController.text.trim();
    try {
      await _prefs.setString(nameKey, name);
      if (!mounted) return;
      setState(() => _savedName = name);
      _showMessage('Name saved.');
    } catch (error) {
      if (mounted) _showMessage('Could not save name: $error');
    }
  }

  // Update the theme immediately, then save the choice.
  Future<void> _changeDarkMode(bool enabled) async {
    setState(() => _darkMode = enabled);
    try {
      await _prefs.setBool(darkModeKey, enabled);
    } catch (error) {
      if (mounted) _showMessage('Could not save dark mode: $error');
    }
  }

  // Slider dragging updates the preview; releasing saves once.
  Future<void> _saveFontSize(double size) async {
    try {
      await _prefs.setDouble(fontSizeKey, size);
    } catch (error) {
      if (mounted) _showMessage('Could not save font size: $error');
    }
  }

  // Remove only the preferences owned by this demonstration.
  Future<void> _restoreDefaults() async {
    try {
      await _prefs.remove(nameKey);
      await _prefs.remove(darkModeKey);
      await _prefs.remove(fontSizeKey);

      if (!mounted) return;
      _nameController.clear();
      setState(() {
        _savedName = '';
        _darkMode = false;
        _fontSize = 18.0;
      });
      _showMessage('Default settings restored.');
    } catch (error) {
      if (mounted) _showMessage('Could not reset settings: $error');
    }
  }

  @override
  void dispose() {
    _nameController.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Persistent Settings Demo',
      debugShowCheckedModeBanner: false,
      scaffoldMessengerKey: _messengerKey,
      theme: ThemeData(
        colorScheme: ColorScheme.fromSeed(seedColor: Colors.indigo),
        useMaterial3: true,
      ),
      darkTheme: ThemeData(
        colorScheme: ColorScheme.fromSeed(
          seedColor: Colors.indigo,
          brightness: Brightness.dark,
        ),
        useMaterial3: true,
      ),
      themeMode: _darkMode ? ThemeMode.dark : ThemeMode.light,
      home: Scaffold(
        appBar: AppBar(title: const Text('Persistent Settings')),
        body: _loading
            ? const Center(child: CircularProgressIndicator())
            : SafeArea(
                child: ListView(
                  padding: const EdgeInsets.all(20),
                  children: [
                    const Text(
                      'Change these settings, close the app, '
                      'and open it again.',
                    ),
                    const SizedBox(height: 24),

                    // Setting #1: String
                    TextField(
                      controller: _nameController,
                      decoration: const InputDecoration(
                        labelText: 'Display name',
                        hintText: 'Enter your name',
                        border: OutlineInputBorder(),
                      ),
                      textInputAction: TextInputAction.done,
                      onSubmitted: (_) => _saveName(),
                    ),
                    const SizedBox(height: 8),
                    ElevatedButton.icon(
                      onPressed: _saveName,
                      icon: const Icon(Icons.save),
                      label: const Text('Save Name'),
                    ),
                    const SizedBox(height: 12),
                    const Divider(),

                    // Setting #2: bool
                    SwitchListTile(
                      title: const Text('Dark mode'),
                      subtitle: const Text('Remember the theme'),
                      value: _darkMode,
                      onChanged: _changeDarkMode,
                    ),
                    const Divider(),

                    // Setting #3: double
                    Text('Preview font size: ${_fontSize.round()}'),
                    Slider(
                      min: 14.0,
                      max: 30.0,
                      divisions: 16,
                      label: _fontSize.round().toString(),
                      value: _fontSize,
                      onChanged: (double value) {
                        setState(() => _fontSize = value);
                      },
                      onChangeEnd: _saveFontSize,
                    ),
                    const Divider(),
                    const SizedBox(height: 16),

                    // Live preview using the saved name and settings.
                    Text(
                      _savedName.isEmpty
                          ? 'Welcome, student!'
                          : 'Welcome, $_savedName!',
                      style: TextStyle(
                        fontSize: _fontSize,
                        fontWeight: FontWeight.bold,
                      ),
                    ),
                    const SizedBox(height: 24),
                    OutlinedButton.icon(
                      onPressed: _restoreDefaults,
                      icon: const Icon(Icons.restart_alt),
                      label: const Text('Restore Defaults'),
                    ),
                  ],
                ),
              ),
      ),
    );
  }
}

Understanding the code

A. The three keys. display_name, dark_mode, and font_size are strings identifying values in device storage. Their exact spelling matters when we read them back. The constant names help avoid typographical errors.

B. The preferences object. final SharedPreferencesAsync _prefs = SharedPreferencesAsync(); creates an interface to asynchronous key-value storage. Unlike the legacy API, we do not call SharedPreferences.getInstance().

C. Starting the load. initState() runs once when the state object is created. It calls _loadSettings(), which reads the saved values. While those reads are underway, the application displays a CircularProgressIndicator.

D. Default values and null. A fresh installation has no saved values. The ?? operator supplies '', false, and 18.0 when a key is absent. The font size is also clamped to the allowed slider range in case stored data is outside that range.

E. Updating the screen versus saving. setState() changes Flutter’s in-memory state and triggers a rebuild. _prefs.setBool(), _prefs.setDouble(), and _prefs.setString() request writes to persistent storage. They do different jobs. The switch both updates the interface and saves its new value.

F. Text input. TextEditingController manages the text field. We use .text.trim() to read the entered name and call .dispose() when the state is destroyed. Unlike the switch, the name is saved only when you press Save Name or submit the field.

G. Slider behavior. onChanged changes the preview immediately as the slider moves. onChangeEnd saves once when the drag ends, avoiding a write on every movement.

H. Removing values. The Restore Defaults button uses remove() for our three keys and restores the starting UI values. Removing only known keys is safer than clearing every preference in a larger app.

I. Asynchrony and errors. Every storage read or write uses await. The try/catch blocks provide basic error messages, and mounted prevents calls to setState() after a widget has been disposed of.

Advanced note, optional reading: Rapid overlapping writes or reset operations can require additional coordination in a production app. For this small demonstration, wait for one operation to finish before testing another. In a larger app, centralize settings management and serialize conflicting writes.

Test persistence

  1. Run the app and enter a name. Select Save Name.
  2. Turn Dark mode on.
  3. Move the slider to a different font size and release it.
  4. Fully terminate the running application, then launch it again. A Flutter hot reload alone is not a persistence test.
  5. Confirm the name, dark mode, and font size have been restored.
  6. Press Restore Defaults, restart again, and confirm the original values return.

Expected results: The name persists after saving; the theme persists after toggling; font size persists after releasing the slider; and reset removes the three saved entries.

Troubleshooting

  • Import not found: Check that you ran flutter pub add shared_preferences inside the correct project directory. Try flutter pub get.
  • Changes disappear: Make sure you saved the name, released the slider, and fully restarted the app rather than only running a hot reload. Check the debug output for storage exceptions.
  • Preferences seem to vanish after reinstalling: Application storage may be removed on uninstall or app-data clearing; do not treat local preferences as an account backup.
  • App will not build: Check flutter --version, flutter doctor, and the package’s SDK constraints. A newly published package version may require a newer Flutter SDK; flutter pub add normally resolves a compatible release.
  • Preference read produces an error: Verify that a given key is always used with the same data type. For example, do not write an int under font_size and then attempt to read it with getDouble().

Customizing the application name and launcher icon

An application has several distinct identifiers and visual elements that determine how it appears inside Flutter and on the device launcher:

Item Where it appears How to change it
App-bar title At the top of the Flutter screen AppBar(title: ...) in main.dart
Flutter application title Used by Flutter/platform integrations; not necessarily the launcher label MaterialApp(title: ...) in main.dart
Installed app name / launcher label Under the app icon on the device home screen and in the app list Android manifest or iOS Info.plist
Launcher icon Home screen / application launcher Platform icon resources, conveniently generated with flutter_launcher_icons

Important: Changing MaterialApp.title does not by itself change the name printed beneath the installed app’s icon. Likewise, changing Icon(Icons.settings) inside the UI does not change the launcher icon.

Step 1 — Choose an application name

Use My Settings or choose another appropriate short name. Short names are less likely to be truncated on mobile home screens.

In lib/main.dart, find the MaterialApp constructor and change its title property:

MaterialApp(
  title: 'My Settings',
  // Keep the rest of your existing properties.
)

Do not replace the whole MaterialApp from the earlier exercise with only this snippet; change the existing property and retain its theme, darkTheme, home, and other settings. Similarly, locate the existing AppBar and change its title to const Text('My Settings') if you want the visible heading to match.

Step 2 — Change the installed application name on Android

Open:

android/app/src/main/AndroidManifest.xml

Inside the existing <application> element, find the android:label attribute. Change only its value:

<application
    android:label="My Settings"
    android:name="${applicationName}"
    android:icon="@mipmap/ic_launcher">
    <!-- Keep the application's existing activity and other configuration. -->
</application>

This is an illustrative excerpt, not a replacement for your entire manifest. Keep all generated <activity>, <meta-data>, and other entries. The ${applicationName} placeholder is part of the generated Flutter Android project and should remain unchanged.

The launcher label is separate from the Android application ID (such as com.example.persistent_settings_demo). Changing the launcher label does not require changing the application ID.

Step 3 — Change the installed application name on iOS

Open:

ios/Runner/Info.plist

Inside the top-level <dict>, locate the CFBundleDisplayName entry and set it to:

<key>CFBundleDisplayName</key>
<string>My Settings</string>

If the key is absent, add this pair inside the main <dict>. Preserve the other entries. CFBundleDisplayName controls the name shown beneath the app icon on iOS. Do not confuse it with the bundle identifier, which is a separate setting.

Platform note: Building for iOS normally requires macOS and Xcode. If you use Windows, complete and test the Android portion; you can still inspect the iOS configuration file if your project contains it.

Step 4 — Prepare a launcher icon image

Create a square PNG image, preferably 1024 × 1024 pixels. Use an original simple design: for example, a gear or slider symbol for this settings application. Keep the essential artwork away from the edges because mobile launchers may mask or crop icons into different shapes. For the basic iOS icon, use an opaque background rather than transparency.

Create these folders in the Flutter project:

persistent_settings_demo/
├── assets/
│   └── icon/
│       └── app_icon.png
├── android/
├── ios/
├── lib/
│   └── main.dart
└── pubspec.yaml

Place the image at assets/icon/app_icon.png. The generator reads this file directly; it does not need a Flutter assets: declaration in pubspec.yaml merely to create launcher icons.

Step 5 — Install the launcher-icon generator

From the project root, run:

flutter pub add --dev flutter_launcher_icons

This adds the tool under dev_dependencies in pubspec.yaml, separate from the shared_preferences runtime dependency. This package is used during development to generate native icon files; the app does not call it from main.dart.

Step 6 — Configure the icon generator

Create a file in the project root named flutter_launcher_icons.yaml (at the same level as pubspec.yaml):

flutter_launcher_icons:
  android: true
  ios: true
  image_path: "assets/icon/app_icon.png"
  remove_alpha_ios: true

This is the documented configuration format for the flutter_launcher_icons package. android: true and ios: true replace the respective default launcher icon assets; remove_alpha_ios helps generate an iOS-compatible opaque icon.

For this introductory exercise, a single source image is sufficient. Production Android applications may additionally benefit from separately designed adaptive icon foreground and background layers and an optional monochrome variant for themed icons.

Step 7 — Generate the icon files

In the project root, execute:

flutter pub get
dart run flutter_launcher_icons

The generator writes platform-specific sizes and resources, rather than using the 1024-pixel source file as-is on every device.

Typical generated locations include:

  • Android: android/app/src/main/res/mipmap-*/ and other icon resources as appropriate.
  • iOS: ios/Runner/Assets.xcassets/AppIcon.appiconset/.

Do not manually rename the files the generator produces without also updating the platform configuration.

Step 8 — Rebuild and verify

Stop the running app and run:

flutter clean
flutter pub get
flutter run

flutter clean is a troubleshooting precaution rather than a requirement for every icon change. Hot reload does not reliably update installed launcher icons or platform manifest metadata; you need a new native build and installation.

Return to the device’s home screen or app drawer and confirm:

  1. The app name below the icon is My Settings.
  2. The icon displays your new artwork instead of Flutter’s default icon.
  3. Opening the app still shows the saved display name, dark-mode setting, and font size after a normal restart.

If the old icon remains, first ensure the icon generation command succeeded and the image path is correct. Then rebuild; if the launcher is caching the old icon, uninstall and reinstall the app only after checking any data you need to preserve, because uninstalling normally removes the app’s locally stored shared preferences.

Common errors

Symptom Likely cause / correction
File not found from the generator Check that assets/icon/app_icon.png exists and the YAML path matches exactly.
Default icon remains Re-run dart run flutter_launcher_icons, stop the app, and rebuild rather than hot reload.
Name changes inside the app, but not below the icon Update android:label or CFBundleDisplayName; MaterialApp.title alone is insufficient.
iOS icon shows unexpected transparency/background Use an opaque square icon and remove_alpha_ios: true.
Settings disappear after testing Uninstalling/reinstalling can remove the app’s stored preferences. Test persistence by closing and reopening the installed app without uninstalling it.

Chapter summary

Flutter state determines what the interface looks like now; shared preferences preserve selected simple values for the next time the application runs. The SharedPreferencesAsync API provides asynchronous access to small, noncritical settings. Application names and launcher icons, in contrast, are configured through native platform metadata and build-time resources.
